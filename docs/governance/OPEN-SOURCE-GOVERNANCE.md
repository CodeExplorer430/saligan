# Open-Source Governance

## Principles

SALIGAN is FOSS and self-hostable. Governance prioritizes user safety, transparent decisions, maintainability, license compatibility, and community review.

## Authority

Maintainers `@chesternothacker` and `@codeexplorer430` control repository access, merge decisions, releases, security response, governance changes, and maintainer appointments. CODEOWNERS identifies required review; it does not replace repository permissions.

## Contributions

- Contributions require traceable scope, review, tests, docs, and license-compatible content.
- Maintainers may request changes, close out-of-scope proposals, or reject unsafe/unmaintainable work.
- AI-assisted contributions are allowed; contributor remains accountable.
- Decisions affecting project direction SHOULD be recorded in issues, ADRs, or governance docs.

## Licensing and Provenance

Before public release, repository MUST contain an approved OSI-compatible license. Dependencies and contributed assets MUST be compatible with that license. Contributors MUST have rights to submitted code, text, designs, and data.

## Security

Vulnerabilities MUST use private reporting instructions in `SECURITY.md` when available. Public issues MUST NOT contain secrets, private records, or actionable undisclosed exploit details.

## Conduct and Enforcement

Before broad public contribution, repository SHOULD add an approved code of conduct and enforcement contacts. Maintainers may moderate abusive, unsafe, spam, or privacy-violating activity.

## Governance Changes

Material changes to authority, licensing, release approval, security response, or contribution rights require maintainer approval and documented rationale.
